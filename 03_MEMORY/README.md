# 03_MEMORY 记忆目录说明

本目录是**已闭环会话的归档区**。

仅当出现闭环触发词（可以了 / ok 了 / 完成 / 开始总结本次会话 / 归档 / 会话结束）时，才向本目录写入会话总结与原始会话两份文件。平时对话和子步骤完成不写入本目录。未闭环会话的原始对话写在根目录 `CURRENT_ORIGINAL.md`，闭环后再迁入本目录。

## 目录结构

```text
03_MEMORY/
├── README.md
└── SESSION/
    ├── SUMMARY/
    └── ORIGINAL/
```

## SESSION/ 会话记忆总区

### 用途

保存每次重要会话产生的记录。

它用于回答：

```text
最近发生过什么？
上次任务做到哪里？
当时讨论了哪些结论？
```

## SESSION/SUMMARY/ 会话总结区

### 用途

保存一次任务或一次重要对话结束后的压缩总结。

这是 Agent 恢复近期任务时优先读取的会话记忆。

### 适合放入

- 本次任务主题
- 已完成内容
- 关键决策
- 未完成事项
- 下一步计划
- 涉及项目
- 涉及文件

### 不适合放入

- 完整聊天原文
- 大量临时想法
- 已被否定且无价值的讨论
- 用户长期偏好
- 项目长期架构决策

### 建议命名

```text
YYYY-MM-DD_主题.md
```

例如：

```text
2026-07-30_AI_OS_framework.md
```

## SESSION/ORIGINAL/ 原始记录区

### 用途

保存完整原始会话、原始讨论记录或重要证据。

它是档案，不是默认记忆。

### 适合放入

- 完整聊天记录
- 用户明确要求保留的原始内容
- 重要决策的原始上下文
- 需要追溯的证据材料

### 不适合放入

- 项目最终结论
- 用户长期偏好
- 技能说明
- 知识卡片

### 读取规则

默认不读取。

仅当用户明确要求（如出现「读取原始会话记录」）时才读取原始记录；读取顺序为先根目录 `CURRENT_ORIGINAL.md`，再 `ORIGINAL/`。

## 与其他目录的区别

```text
02_USER_CONTEXT/
= 用户是谁、用户怎么工作、用户喜欢什么协作风格

04_PROJECTS/<PROJECT>/MEMORY.md
= 某个项目长期有效的决策和经验

03_MEMORY/SESSION/SUMMARY/
= 某次任务的恢复摘要

03_MEMORY/SESSION/ORIGINAL/
= 某次任务的完整原始档案
```

## 写入规则

- 仅在闭环触发词出现时写入本目录，一次写两份：总结到 `SUMMARY/`，原始到 `ORIGINAL/`。
- 未闭环但需后续跟进（中断触发词）时，原始对话写到根目录 `CURRENT_ORIGINAL.md`，不写本目录。
- 曾中断的会话最终闭环时，根目录 `CURRENT_ORIGINAL.md` 迁入 `ORIGINAL/`（加日期戳），根目录文件移除。
- 无触发词的平时对话与子步骤完成，不写入本目录，避免 token 浪费。
- 项目长期有效的信息提炼到项目 `MEMORY.md`。
- 用户跨项目长期有效的信息提炼到 `02_USER_CONTEXT/`。
- 具体触发词与路由见 `01_SYSTEM_RULES/AGENT_COMMON_RULES.md` 的记忆写入规则。
