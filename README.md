# AI_OS v1.0 总说明

AI_OS 是一个面向多个 AI Agent 的共享工作空间。

它的目标不是把所有信息都塞进上下文，而是让不同 Agent 在需要时能够快速读取同一套规则、用户配置、当前状态、项目记忆、技能、知识和输出文件，从而实现低 Token、可接续、可长期沉淀的协作。

## 总体结构

```text
AI_OS/
├── CURRENT_CONTEXT.md
├── 00_BOOTSTRAP/
├── 01_SYSTEM_RULES/
├── 02_USER_CONTEXT/
├── 03_MEMORY/
├── 04_PROJECTS/
├── 05_SKILLS/
├── 06_KNOWLEDGE/
└── 07_OUTPUTS/
```

## 各部分用途

### CURRENT_CONTEXT.md

当前工作状态文件。用于告诉 Agent 现在正在做什么、做到哪里、下一步是什么。

它是高频读取文件，但不是历史仓库，也不是长期记忆。只保留当前仍然有效的信息。

### 00_BOOTSTRAP/

Agent 启动入口。用于说明 Agent 进入 AI_OS 后应该按什么顺序读取文件、如何控制 Token、如何开始接管任务。

### 01_SYSTEM_RULES/

系统规则层。保存所有 Agent 必须遵守的底层行为规则，例如 Token 优化、真实性、验证、最小修改、记忆读写规则。

系统规则优先级高于用户偏好和项目规则。

### 02_USER_CONTEXT/

用户上下文层。保存用户是谁、用户如何工作、用户希望 Agent 以什么风格协作。

它不是强制系统规则，而是 Agent 适配当前用户的配置层。

### 03_MEMORY/

会话记忆层。保存会话总结和原始会话记录。

会话总结用于恢复近期任务，原始记录只用于追溯证据，不默认读取。

### 04_PROJECTS/

项目工作区。每个长期项目都应该有自己的目录、任务文件、项目记忆、代码、文档和数据。

项目级长期知识应沉淀到项目内的 `MEMORY.md`。

### 05_SKILLS/

技能库。保存通用技能和 Agent 专属技能。

Agent 应先读取技能索引，再按任务需要加载具体技能文件。

### 06_KNOWLEDGE/

个人知识库。保存原始资料、整理后的知识和未来可能使用的向量索引。

知识库不应默认全量读取，应按主题和任务检索。

### 07_OUTPUTS/

输出资产区。保存 Agent 生成的代码、文档、数据、工具等可复用成果。

重要输出不应只留在聊天窗口中。

## Agent 默认工作流程

```text
打开 Agent
-> 读取 00_BOOTSTRAP/BOOTSTRAP.md
-> 读取 01_SYSTEM_RULES/RULES_INDEX.md
-> 加载必要系统规则
-> 读取 02_USER_CONTEXT/
-> 读取 CURRENT_CONTEXT.md
-> 识别任务类型
-> 按需加载项目、技能、知识、会话总结
-> 小范围执行
-> 验证结果
-> 交付任务
-> 总结有价值信息
-> 更新记忆和当前状态
```

## 核心原则

```text
全量保存
最小读取
按需加载
小范围验证
验证后交付
有价值才沉淀
```

## 不应该做的事

- 不要默认读取整个知识库。
- 不要默认读取完整历史会话。
- 不要把临时想法全部写入长期记忆。
- 不要把用户偏好混入系统强制规则。
- 不要为管理而管理，避免框架过度复杂。
