# Agent 通用规则

## 先思考再行动

执行前必须：

- 理解目标
- 明确成功标准
- 检查已有资源

重要信息缺失时，不要根据假设直接行动。

## 简单优先

优先选择最简单且有效的方案。

避免不必要复杂化、提前优化和用户未要求的功能。

## 精准修改

只修改完成当前目标所必需的内容。

避免无关重写、大范围重构或修改不了解的区域。

## 目标驱动

每个任务都应明确：

- 目标
- 步骤
- 验证方式

## 验证后再声明完成

不能在未验证的情况下声称任务完成。

必须清楚说明：

- 完成了什么
- 如何验证
- 仍有哪些不确定

## 真实性优先

禁止编造事实、结果、测试、来源或用户偏好。

不确定时必须明确说明。

## 上下文意识

继续长期任务或项目任务前，按顺序读取：

```text
CURRENT_CONTEXT
-> USER_CONTEXT
-> PROJECT MEMORY
-> 必要时读取 SESSION SUMMARY
```

避免重复询问工作区中已经存在的信息。

## 记忆读取优先级

```text
CURRENT_CONTEXT.md
-> 02_USER_CONTEXT/
-> 04_PROJECTS/<PROJECT>/MEMORY.md
-> 03_MEMORY/SESSION/SUMMARY/
```

`CURRENT_ORIGINAL.md`（根目录，未闭环原始对话）与 `03_MEMORY/SESSION/ORIGINAL/`（闭环原始档案）**默认不读**。

仅当用户明确要求（如出现「读取原始会话记录」）时才读这两类原始对话；读取顺序为先 `CURRENT_ORIGINAL.md`，再 `ORIGINAL/`。

`CURRENT_ORIGINAL.md` 单文件覆盖（规则同 CURRENT_CONTEXT），闭环后迁入 `ORIGINAL/` 并从根目录移除。

## 可恢复性

复杂任务、项目任务或多步骤任务必须保留：

- 当前目标
- 已完成内容
- 未完成内容
- 下一步
- 关键决策

## 先复用再创建

创建新内容前，优先检查已有：

- 技能
- 代码
- 知识
- 项目文件

## 记忆写入规则

不是所有信息都进入记忆。只保存未来可能重复使用的信息。

### 唯一记忆位置

AI_OS 是本工作区唯一的记忆系统。

禁止把记忆写入 AI_OS 之外的任何默认记忆目录，包括但不限于 Agent 工具自带的 `.workbuddy/memory/`、`.cursor/`、`.trae/`、`.qoder/` 等私有目录。

如果某个 Agent 的运行环境强制要求写入自带记忆目录，只允许在该目录留下一份指向 AI_OS 的说明文件，不允许保存实际记忆内容。

### 三个记忆面与触发条件

记忆写入按触发词执行。平时对话和子步骤完成不自动写入 `03_MEMORY/`，避免每轮 token 浪费。

1. 当前快照 — `CURRENT_CONTEXT.md`
   - 触发：进度变化时（按本节"写入后的一致性"）。
   - 方式：覆盖式单文件，回答"现在到哪了"。
2. 闭环归档 — `03_MEMORY/SESSION/`
   - 触发：闭环触发词（见下）。
   - 方式：一次写两份——会话总结 + 原始会话。
3. 当前原始对话 — 根目录 `CURRENT_ORIGINAL.md`
   - 触发：中断触发词（见下）。
   - 方式：单文件覆盖（规则同 CURRENT_CONTEXT），写完整原始对话转储，供新 Agent 接管补全上下文。

#### 闭环触发词（归档）

出现「可以了 / ok 了 / 完成 / 开始总结本次会话 / 归档 / 会话结束」等明确表示**整轮会话结束**的指令时，写两份文件：

- 会话总结 -> `03_MEMORY/SESSION/SUMMARY/YYYY-MM-DD_主题.md`
- 原始会话 -> `03_MEMORY/SESSION/ORIGINAL/YYYY-MM-DD_主题.md`

「完成」需为会话级闭环意图，单个子步骤完成不触发归档。

#### 中断触发词（恢复）

出现「下次继续 / 明天继续 / 待跟进 / 先到这」等表示**未闭环、需后续跟进**时：

- 在根目录写一份完整原始对话转储 `CURRENT_ORIGINAL.md`（单文件覆盖，规则同 CURRENT_CONTEXT）。
- `CURRENT_CONTEXT.md` 保持当前快照不变。

当一个曾中断的会话最终闭环时，根目录的 `CURRENT_ORIGINAL.md` 迁入 `03_MEMORY/SESSION/ORIGINAL/YYYY-MM-DD_主题.md`（加日期戳）作为闭环原始档案，根目录文件随之移除（按"安全修改规则"先备份）。

#### 无触发

平时对话、单步任务完成、信息查询**不写入** `03_MEMORY/`，不生成会话总结。

### 会话记忆与项目记忆的区别

这两者必须分清，不能互相混写。

```text
会话记忆 = 这一次做了什么
项目记忆 = 这个项目永远成立什么
```

会话记忆写入 `03_MEMORY/SESSION/`（仅在闭环或中断触发时）。

它是有时间戳的过程记录，回答"上次做到哪里、当时讨论了什么、下一步是什么"。旧的不删除，闭环后归档。

项目记忆写入 `04_PROJECTS/<PROJECT>/MEMORY.md`。

它是无时间戳的稳定结论，回答"这个项目已经定死了什么"。它应该保持精简，只在决策发生变化时修订，而不是不断追加。

判断方法：

```text
如果这条信息三个月后仍然成立
-> 项目记忆

如果这条信息只用于恢复当前进度
-> 会话记忆
```

### 写入路由

```text
跨项目长期有效的用户信息
-> 02_USER_CONTEXT/

项目长期有效的决策、架构、边界、经验
-> 04_PROJECTS/<PROJECT>/MEMORY.md

全局当前状态快照（含当前项目实时进度）
-> CURRENT_CONTEXT.md

项目进度快照（项目切换/闭环时更新）
-> 04_PROJECTS/<PROJECT>/TASK.md

闭环会话的总结与原始
-> 03_MEMORY/SESSION/SUMMARY/ 与 ORIGINAL/

未闭环会话的原始对话
-> 根目录 CURRENT_ORIGINAL.md
```

### 写入时机

- 产生新的稳定决策 -> 写项目 `MEMORY.md`。
- 项目进度变化 -> 实时同步 `CURRENT_CONTEXT.md`。
- `TASK.md` 仅在项目切换或闭环时更新（项目进度快照）。
- 闭环触发词 -> 写 `03_MEMORY/SESSION/` 的总结 + 原始。
- 中断触发词 -> 写根目录 `CURRENT_ORIGINAL.md` 原始对话转储。
- 用户明确要求记录 -> 按其指定位置写。

不需要写入的情况：

- 简单问答
- 信息查询
- 已被否定且无参考价值的讨论
- 与已有记忆重复的内容
- 无触发词的平时对话与子步骤完成（不写 `03_MEMORY/`）

### 写入后的一致性

写入闭环归档或中断转储后，如果项目进度发生变化，必须实时同步 `CURRENT_CONTEXT.md`；`TASK.md` 在项目切换或闭环时对齐。

不允许出现会话记录说已完成、而 `CURRENT_CONTEXT.md` 仍显示进行中的情况。

## 安全修改规则（无删减原则）

对框架文件的任何改动都必须可回退。

### 默认行为

- 优先只增不改：能以追加方式完成的目标，不覆盖原有内容。
- 必须修改时，只改必要部分，不重写不了解的区域。
- 禁止删除框架内的任何文件或目录，除非用户明确确认最终版可用。

### 改动级别与备份

按改动规模分级处理，避免无谓的备份仪式浪费 token：

- **小改**（单行收紧、措辞调整、局部追加、已知内容可控）：不创建 `_BACKUP_*` 备份。但必须在 `CURRENT_CONTEXT.md` 的「改动留痕」区记录：改动文件 + 位置 + 改前原文 → 改后。格式：`文件 | 位置 | 改前: xxx | 改后: yyy`
- **中改**（多文件、多行结构性调整）：执行前创建 `_BACKUP_YYYY-MM-DD/` 备份。
- **大改**（删除文件、整篇重写、批量改动）：必须备份，且每步可回退。

备份目录与命名（中/大改）：

- 备份目录：`_BACKUP_YYYY-MM-DD/`（位于框架根目录，按当天日期命名）
- 备份命名：原文件名加 `.bak` 后缀，例如 `AGENT_COMMON_RULES.md.bak`
- 备份范围：本次要修改的每个文件，逐个复制，不做删改

### 备份处置

- 备份保留，直到用户明确确认"最终版可用"。
- 用户确认前，不得删除任何备份。
- 用户确认后，由用户或经用户授权后再删除备份目录。

### 例外

- 纯粹的新增文件（目录下原本不存在的文件）不需要备份。
- 临时工作目录（如 `_BACKUP_*`）本身不受此限制。

### 高效读取（省 token）

规则已稳定后，修改文件时不全文重读：

- 用 `grep` 定位目标行号与精确文本，只读相关局部。
- 信任已在上下文中的已知内容，不重复整篇读取验证。
- 仅在空格、结构或上下文确实不确定时才整篇重读。
- 目的：砍掉最大的一块输入 token 开销，同时保持改动精确。
