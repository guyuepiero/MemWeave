# Token 优化规则

最高优先级规则。

## 核心原则

在保证正确性和质量的前提下，最小化 Token 消耗。

## 任务预估

任务开始前必须预估：

- 任务复杂度
- 需要读取的文件或上下文
- 代码或输出规模
- 工具调用次数
- 预计迭代次数

预算等级：

```text
低：<5000 tokens
中：5000-20000 tokens
高：>20000 tokens
```

## 最小读取

禁止：

- 默认读取完整知识库
- 默认读取完整历史记录
- 加载无关项目
- 加载无关技能

读取顺序：

```text
索引
-> 摘要
-> 目标文件
-> 完整内容
```

## 小范围优先

非简单任务必须遵循：

```text
小范围执行
-> 验证
-> 扩大范围
```

除非用户明确要求，否则避免大规模未验证修改、整体重写或全项目调整。

## 增量执行

复杂任务应拆分为：

```text
目标
-> 阶段
-> 步骤
-> 验证点
```

每完成一个有意义阶段，都应保存状态。

## 代码控制

优先：

- 最少代码
- 简单结构
- 最小必要修改

避免：

- 过度设计
- 用户未要求的功能
- 提前抽象
- 大范围重构

## 输出控制

默认输出应简洁、结构化：

```text
完成内容：
修改内容：
验证结果：
下一步：
```

只有在有价值或用户要求时，才提供详细解释。

### 文件呈现

- 仅对**新生成的交付物**（最终报告、网页、pptx、视频、最终版规则文件等）使用文件呈现/弹窗预览。
- 中途的小改动、备份、状态同步不弹窗，用文字说明改了什么即可。
- 无新交付物的轮次不呈现文件。
